## Ожидаемый ответ

Ручной и автоматический git bisect должны обнаружить один и тот же первый
ошибочный коммит. Его родитель должен проходить проверку, а сам коммит — не
проходить. После исправления calc.py тест должен выводить OK.

## Моё объяснение

С помощью git blame calc.py я определил, в каком коммите была изменена строка с
вычислением результата.

Затем с помощью git bisect выполнил бинарный поиск первого ошибочного коммита
между history-good и lab-start.

В результате был обнаружен коммит e590f413 («История 08: изменение проекта»).
Ошибка заключалась в использовании сложения вместо умножения:

return 2 + n + STUDENT_NUMBER

Правильное выражение:

return 2 \* n + STUDENT_NUMBER

После завершения поиска я выполнил git bisect reset, исправил calc.py и проверил
результат командой python3 check.py. Проверка вывела OK.

Исправление сохранено отдельным коммитом 8d3fb08 и опубликовано на GitHub.
