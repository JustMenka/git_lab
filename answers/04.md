## Ожидаемый ответ

Команда git revert должна создать новый коммит, отменяющий изменения указанного
коммита, но не удаляющий его из истории.

Команда git restore --source=Y^ -- settings.ini должна восстановить только файл
settings.ini из родительского коммита Y. Остальные файлы должны остаться без
изменений.

В результате исходные коммиты сохраняются в истории, а отмена изменений и
восстановление файла фиксируются отдельными коммитами.

## Моё объяснение

Сначала я изучил коммит X (41a3cdb) с помощью git show. Он изменял два файла:
message.txt и settings.ini.

Затем выполнил git revert 41a3cdb. Git создал коммит d6e6916, который отменил
изменения X. При этом сам X остался в истории, а содержимое файлов вернулось к
исходному состоянию.

После этого я создал коммит Y (b7937cc), изменив settings.ini на
mode=production, а message.txt на Сообщение: новая версия Y.

С помощью git restore --source=HEAD^ -- settings.ini восстановил только
settings.ini из родительского коммита Y. Файл message.txt при этом не изменился.

Восстановление сохранил отдельным коммитом 8ddf01a.

В результате settings.ini содержит mode=training, а message.txt — Сообщение:
новая версия Y. Рабочая директория и индекс чистые.

В отличие от git reset, команда git revert не переписывает историю, поэтому для
публикации изменений было достаточно обычного git push.

`Ожидаемый ответ: revert создаёт новый коммит для отмены коммита; для одного файла используется restore.`
