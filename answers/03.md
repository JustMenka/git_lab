## Ожидаемый ответ

Команда git commit --amend позволяет заменить последний коммит, изменив его
сообщение или содержимое.

Интерактивный git rebase -i позволяет редактировать историю нескольких коммитов.
Команда reword изменяет сообщение выбранного коммита, а squash объединяет его с
предыдущим.

В результате переписывания истории SHA коммитов изменяются. При этом итоговое
содержимое файлов может остаться прежним. Для публикации переписанной истории
используется git push --force-with-lease.

## Моё объяснение

Сначала я исправил сообщение последнего коммита C4 с tmp на story: завершить
изменения` с помощью git commit --amend. SHA изменился с a791c58 на 9301ac8.
После этого я выполнил первый git push --force-with-lease.

Затем запустил git rebase -i cca202. С помощью reword изменил сообщение C1 с wip
на story: начать работу над историей. Коммит получил новый SHA 462241b.

С помощью squash объединил коммиты C2 (f15d5ce) и C3 (4bd6439) в один коммит
eeef393 с сообщением story: добавить строку и исправить опечатку.

Последний коммит C4 также получил новый SHA c5878b2, поскольку при rebase
изменилась цепочка родительских коммитов.

В результате вместо четырёх коммитов осталось три. После второго git push
--force-with-lease локальная и удалённая ветки синхронизированы.

Команда git diff evidence/03-before feature/task-03 не показала различий. Это
подтверждает, что изменения затронули только историю коммитов, а итоговое
содержимое файлов сохранилось.

Ожидаемый ответ: amend меняет SHA последнего коммита; reword меняет сообщение;
squash объединяет два коммита; в результате три содержательных коммита.
